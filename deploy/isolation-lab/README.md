# Изоляция редакторов и проверочный стенд

Режим включается параметром `workerIsolation.mode = "bubblewrap"` штатного
портала. По умолчанию сохраняется обычный TCP-запуск. Это не система
одновременного согласования сцен и не независимый аудит безопасности.

## Условия запуска

Linux с glibc, Node.js 24, bubblewrap и util-linux (`flock`, `runuser`),
разрешённые непривилегированные user namespaces. Портал и редакторы работают
без root. Ограничения AppArmor/systemd нужно проверить на выбранном сервере.
Режим испытан на Debian 12 / bubblewrap 0.8 и Ubuntu 24.04 / bubblewrap 0.9.
Проверки ниже изменяют только новые каталоги синтетического стенда.

1. Подготовьте движок обычной командой `npm run setup` из корня репозитория.
2. Используйте [конфигурацию](../config-isolation.example.json): канонический
   `appRoot` конкретного релиза и отдельные папки каждой фиксированной доски.
3. Проверьте доступ пользователя к Node, движку и собственным данным. Не
   монтируйте общий корень данных: там могут находиться auth и соседние доски.
4. Укажите общий `maxWorkers`, достаточный для постоянных и личных редакторов,
   и отдельный лимит памяти службы. Пример не задаёт подходящий лимит для VPS.

Движок read-only, данные только одной доски writable, внешней сети и процессов
хоста в песочнице нет. HTTP/WebSocket идут через Unix-сокет. Реальный Node
монтируется в `/runtime/node`, его расположение на хосте не фиксировано.
Lease-файл хранится вне папки редактора и монтируется read-only. Kernel flock
обеспечивает одного писателя, readiness проверяет поколение конкретного запуска.

## Проверки на вымышленных данных

Все команды выполнять из канонического пути репозитория от обычного Linux
пользователя. Сначала создайте новый пустой каталог вне production-данных:

```sh
export BOARDS_LAB_STATE="$(mktemp -d /tmp/boards-isolation-XXXXXX)"
node deploy/isolation-lab/check-boundaries.mjs "$BOARDS_LAB_STATE/boundaries"
node deploy/isolation-lab/check-lifecycle.mjs "$BOARDS_LAB_STATE/lifecycle"
node deploy/isolation-lab/check-recovery.mjs "$BOARDS_LAB_STATE/recovery"
node deploy/isolation-lab/prepare-functional.mjs
node --test --test-timeout=120000 .local/isolation-members.test.mjs
```

Каталог репозитория и `.local` должны быть writable этому пользователю.
Генератор функционального сценария использует настоящий `portal/server.mjs`
с отдельным конфигом, не меняет исходный `tests/members.test.mjs`.
Отдельно запустите `npm test`, `npm run test:upstream` и
`npm run check:dependencies`. Если изменены frontend/доступы, выполните
`node tests/browser-security.mjs` в среде с установленным Chromium Playwright.

Дополнительная репетиция миграции требует отдельно собранного прежнего
TCP-движка с патчами 001-006, а не пути работающего сервера:

```sh
node deploy/isolation-lab/check-migration.mjs "$BOARDS_LAB_STATE/migration" /path/to/previous-six-patch-engine
```

Она записывает вымышленную сцену, изображение и snapshot, проверяет отказ
захвата живого writer, stopped backup, новый движок, возврат прежнего движка
и запуск отдельно восстановленной копии. Не указывайте существующие рабочие
каталоги ни в качестве стенда, ни в качестве резервной копии.

`demo.mjs /path/to/new/fixture 8806` поднимает локальный стенд с тремя
фиксированными и личными досками. Пароль в этом скрипте вымышленный и публичный;
его нельзя использовать вне локальной демонстрации. `probe.mjs` используется
только тестом границ, не является API выполнения произвольного кода.

## Восстановление и пределы защиты

После аварии нельзя стирать owner по проверке PID хоста или удалять lease.
Сначала остановите писателей. `recover-stopped.mjs` принимает проверенный JSON
в stdin, последовательно захватывает kernel lease и чисто останавливает
редакторы. Legacy/неизвестные owners, подменённые lease или socket отвергаются.
После успешного восстановления делайте новую offline-копию.
Подробности: [эксплуатация](../../docs/operations.md).

Песочница ограничивает компрометацию одного редактора. Уязвимость портала,
ядра, ошибки прав доступа или нехватка памяти остаются отдельными рисками.
Защита Caddy требует отдельной установки, не возникает от включения bubblewrap.
Исторические этапы: [прототип](../../docs/isolation-lab-verification-20261025.md),
[штатный запуск и recovery](../../docs/isolation-recovery-verification-20261025.md).
