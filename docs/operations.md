# Данные и эксплуатация

Конфиг выбирается переменной PORTAL_CONFIG, по умолчанию config.local.json.
Относительные пути разрешаются от корня установки. Для сервера используйте
абсолютные пути вне каталога сменяемого релиза:

```json
{
  "localDemo": false,
  "origin": "https://boards.example.org",
  "host": "127.0.0.1",
  "port": 8805,
  "appRoot": "/srv/boards-portal/current/.vendor/upstream",
  "dataRoot": "/var/lib/boards-portal",
  "authStateFile": "/var/lib/boards-portal/auth.json",
  "boardsConfig": "/etc/boards-portal/boards.json",
  "personalDataRoot": "/var/lib/boards-portal/personal",
  "maxWorkers": 2,
  "idleMs": 120000
}
```

Для существующей установки укажите её действующие пути. Не копируйте рабочие
значения в Git. Никакая команда старта не создаёт пользователей и не сбрасывает
данные. demo:init предназначен только для новой локальной демонстрации.

Перед копированием остановите портал и все редакторы, использующие эти
данные. Команда резервирования:

```text
npm run backup -- --data-dir /path/to/stopped/data --out /path/to/new/private-backup
```

Копия содержит пароли в виде хешей, права и ключи доступа в виде хешей;
обращайтесь с ней как с конфиденциальными данными. Скрипт отказывается
копировать активные хранилища, символические ссылки и пересекающиеся пути.
Он не собирает автоматически отдельно размещённые конфиги, auth или
фиксированные сцены: включите все настроенные пути в эксплуатационный план.
На Windows права файлов дополнительно зависят от ACL родительской папки.

Восстановление сначала проверяют в отдельном каталоге с другим портом.
Нельзя без разбора возвращать старый auth: это может восстановить отозванный
доступ и потерять новые записи. Локальные файлы ключей, скачанные настройки
Windows и копии никогда не включаются в репозиторий.

## Режим изоляции Linux

Конфигурация выше показывает обычный TCP-режим. Для bubblewrap используйте
[отдельный пример](../deploy/config-isolation.example.json) и
[проверки](../deploy/isolation-lab/README.md). `appRoot` должен быть полным
каноническим путём конкретного релиза, без ссылки `current`. Портал запускают
от непривилегированного пользователя; нужны bubblewrap, flock, user namespaces
и совместимая политика ядра. Нельзя исправлять несовместимость отключением
защиты всего хоста без отдельного исследования.

Каждая запись `fixedDirectories` указывает на папку одной доски с её `canvas/`.
Не выдавайте редактору общий dataRoot, auth или папки соседних досок. Старые
службы фиксированных редакторов останавливают до запуска общего пула.
`maxWorkers` включает все редакторы, но не заменяет общий cgroup-лимит памяти.
Изменение лимитов требует измерения потребления на целевом сервере.

После аварии сначала остановите портал и убедитесь, что писателей не осталось.
Не удаляйте `.leases` и owner-файлы вручную: PID внутри namespace не является
PID хоста. Для известного isolated owner предусмотрен контролируемый
[восстановитель](../deploy/isolation-lab/recover-stopped.mjs). Он запускает
выбранные редакторы по одному под kernel lease и чисто завершает их. Входной
JSON содержит `appRoot`, `personalDataRoot`, `fixedDirectories`, `boards`.
Используйте только проверенную приватную конфигурацию, прежние ID и остановленные
данные. При неизвестном владельце процедура отказывает, его нужно исследовать.
Затем повторите offline backup в новый каталог. Восстановление полной старой
копии auth не является обычным способом отката кода.

Unix-сокет и файловая песочница защищают редактор, но не весь портал. Отдельный
[пример Caddy guard](../deploy/security/README.md) ограничивает доступ сервисного
UID к локальному admin API. Установка guard не входит в `npm start` или релиз.

Для Unix-сокетов используйте короткие канонические каталоги данных.
Linux ограничивает длину пути AF_UNIX (обычно 107 байт без завершающего NUL);
учитывайте добавляемые ID доски и `/editor.sock`. Длинный путь может помешать
запуску редактора, даже если права файловой системы настроены правильно.
