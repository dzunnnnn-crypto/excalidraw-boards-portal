# Одна кодовая база и обновления

Все дальнейшие доработки ведутся в этом репозитории. Локальная демонстрация
и сервер используют один код; различаются конфигурация и данные.

1. Изменить код, проверить npm test и npm run test:upstream.
2. Сохранить проверенный commit. Отправка на GitHub выполняется отдельно.
3. В Linux с glibc и Node 24 выполнить npm run setup, затем
   npm run release -- --out /path/to/new/release.
4. Проверить manifest.json и SHA256 архива, испытать его отдельно.
5. Устанавливать на VPS только выбранный проверенный выпуск.

Релиз содержит исходный commit, версию upstream, SHA патчей, платформу и
stateSchema:2. Windows node_modules на Linux не переносятся. Публикация
GitHub не запускает автоматическое обновление. Если правка сделана на
сервере, её необходимо вернуть в основной код до следующего релиза.

Перед первым переходом существующего VPS нужно заново сверить действующие
current, unit-файлы всех редакторов, Caddy, пути auth/сцен/изображений и
приватных конфигов. Это нельзя определить только по старому README.
Из-за нового пути .vendor/upstream может понадобиться поправить пути запуска
портала и фиксированных редакторов; одного переключения ссылки недостаточно.

Далее: остановить записи, сохранить согласованную копию всех данных и
текущего кода/затрагиваемых конфигов, поставить релиз рядом со старым,
проверить настройки без инициализации и переключить только нужные службы.
Проверить HTTPS, существующие URL/ID, вход, роли, гостевые ссылки, личные
ключи MCP, изображения и совместимость существующего Telegram-клиента.
Сообщения людям для технической проверки не отправляются.

Откат возвращает прежний код и пути запуска, сохраняя текущие данные
version:2. Не запускать demo:init и не заменять auth старой копией вслепую.
Нельзя одновременно запускать два редактора записи одного каталога сцены.
Если понадобится миграция формата данных, нужен отдельный план и испытанный
откат: текущая подготовка формат не меняет.

Эта инструкция не является разрешением менять VPS. Публикация GitHub и
переключение сервера требуют отдельных поручений.
